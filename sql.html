Sheet 00

Before you start

Tables, keys and the one sentence the whole language is built around. Nothing here is SQL you have to write yet.

Relational databases

A is a set of two-dimensional tables. Each row is one instance of the thing the table is about, and each column is one property of it. A column holds the same type of value in every row.

The three words
  • Table — one kind of thing. Also called a relation.
  • Row — one of them. Also called a record.
  • Column — one property of all of them. Also called a field.

Keys

The is the column whose value is different in every row, so a value identifies exactly one row. A is a column in another table holding those same values. That shared value is what a join on sheet 04 matches on.

SQL

is the language used to read and change what a relational database holds. It is declarative: the query describes the result, and the database works out how to produce it.

A reads and returns rows and changes nothing. INSERT, UPDATE and DELETE change the data, and CREATE, ALTER and DROP change the tables; those are sheets 09 and 10.

The shape of a query

The form
SELECT  which columns  FROM  which table;

Every clause added from sheet 02 onwards goes into that sentence in a fixed position.

Nothing to drill yet

This sheet has not taught a query yet. Test mode draws on every sheet up to the one you are on, so it fills up as the sheets do — sheet 01 onwards has questions.

Sheet 01 · SQLBolt lesson 1

SELECT queries 101

SELECT and FROM.

SELECT and FROM

A query names the columns to return and the table to take them from. The result is a table with one column for each one named, in the order they were named, and one row for each row in the source.

The form
SELECT column, another_column, …FROM mytable;

SELECT *

An asterisk returns every column, in the table's own order.

The form
SELECT *FROM mytable;

It is the quickest way to see what an unfamiliar table contains. Naming the columns instead makes the query say what it is for, and keeps its shape when a column is added.

The parts

PartWhat it is
KeywordA word the language reserves, such as SELECT or FROM. Capitals are convention only; select runs identically.
ClauseA keyword and what belongs to it. SELECT Title, Year is the select clause, FROM movies the from clause. Clauses go in a fixed order.
StatementThe whole instruction, ended with a semicolon, which is what separates one statement from the next.
IdentifierThe name of a table or a column, such as movies or Length_minutes. Case does not matter in SQLite.

Line breaks and extra spaces are ignored, so a clause per line costs nothing and reads better once there is more than one.

Two that get confused

SELECT chooses columns. WHERE chooses rows, and that is the next sheet. A lesson-1 query always returns every row the table holds.

Sheet 02 · SQLBolt lessons 2 and 3

Constraints

WHERE, and the numeric and text operators that go in it.

WHERE

Lesson 1 could only choose columns. WHERE chooses rows: the condition is tested against every row, and the row is returned if it comes back true.

The form
SELECT column, another_columnFROM mytableWHERE condition    AND/OR another_condition;

Numeric operators

OperatorCondition
=, !=, <>Equal to, not equal to.
<, <=, >, >=Less than, less than or equal to, greater than, greater than or equal to.
BETWEEN … AND …Within a range, including both ends.
NOT BETWEEN … AND …Outside a range, excluding both ends.
IN (…)Exists in a list.
NOT IN (…)Does not exist in a list.

Text operators

Text goes in single quotes, and can be compared with the operators above as well as these two.

OperatorCondition
LIKECase-insensitive exact match, and the operator that takes the two wildcards below.
%Used with LIKE. Matches any sequence of characters.
_Used with LIKE. Matches exactly one character.
Case

LIKE is case-insensitive in SQLite and MySQL and case-sensitive in PostgreSQL. = is case-sensitive everywhere.

AND, OR, NOT

Conditions combine with AND, OR and NOT. AND binds tighter than OR, so use brackets where the reading is not obvious.

Sheet 03 · SQLBolt lessons 4 and 5

Filtering and sorting

DISTINCT, ORDER BY, LIMIT and OFFSET.

DISTINCT

Discards duplicate rows. It compares the whole selected row, so two columns give you distinct pairs rather than distinct values of either one.

The form
SELECT DISTINCT column, another_columnFROM mytableWHERE condition(s);

ORDER BY

Sorts the result alphabetically or numerically. ASC is the default and can be left off; DESC reverses it. Sort on more than one column by separating them with commas.

The form
SELECT column, another_columnFROM mytableWHERE condition(s)ORDER BY column ASC/DESC;

LIMIT and OFFSET

LIMIT caps the number of rows returned. OFFSET says how many to skip first. They are applied after the sort, which is what makes ORDER BY … DESC LIMIT 5 the top five.

The form
SELECT column, another_columnFROM mytableWHERE condition(s)ORDER BY column ASC/DESCLIMIT num_limit OFFSET num_offset;
The full form, so far
  • SELECT — which columns
  • FROM — which table
  • WHERE — which rows
  • ORDER BY — in what order
  • LIMIT / OFFSET — how many, from where

Sheet 04 · SQLBolt lesson 6

Joins

INNER JOIN: reading two tables as one, on a value they share.

Why the data is in more than one table

Databases are usually normalised: entity data is split across tables so that each piece of information is stored once. The cost is that answering a question often needs more than one table at a time.

INNER JOIN

A join reads two tables as one, matching rows on a value they share — usually a in one table and the column that references it in the other.

The form
SELECT column, another_table_columnFROM mytableINNER JOIN another_table    ON mytable.id = another_table.idWHERE condition(s)ORDER BY column ASC/DESCLIMIT num_limit OFFSET num_offset;

INNER JOIN may be written as JOIN; they mean the same thing. It matches rows from the first table against rows from the second where the key is the same, and discards any row with no match on either side.

Qualifying and aliasing

With two tables in play a column name is written table.column where it would otherwise be ambiguous. A table alias shortens that: FROM movies m, then m.Title. AS is optional. Once a table is aliased, the alias replaces the name for the rest of the query.

Sheet 05 · SQLBolt lessons 7 and 8

Outer joins and NULLs

LEFT, RIGHT and FULL JOIN, and testing for NULL.

LEFT, RIGHT and FULL JOIN

An inner join drops rows without a match. An outer join keeps them.

JoinWhat it returns
INNER JOINOnly rows with a match in both tables.
LEFT JOINEvery row of the first table, plus the matches from the second.
RIGHT JOINEvery row of the second table, plus the matches from the first.
FULL JOINEvery row of both tables.
The form
SELECT column, another_columnFROM mytableINNER/LEFT/RIGHT/FULL JOIN another_table    ON mytable.id = another_table.matching_idWHERE condition(s)ORDER BY column ASC/DESCLIMIT num_limit OFFSET num_offset;

OUTER is optional: LEFT JOIN and LEFT OUTER JOIN are the same statement.

NULLs

Rows kept by an outer join with nothing to match have NULL in the other table's columns, so a query using outer joins has to expect them.

NULL cannot be compared with = or !=. Testing it takes its own operators.

Testing for NULL
  • WHERE column IS NULL
  • WHERE column IS NOT NULL

Where it can be avoided, it is better to give a column a default of 0 or an empty string than to allow nulls into it, because everything downstream then needs no special handling.

Sheet 06 · SQLBolt lesson 9

Expressions

Expressions in SELECT, WHERE and ORDER BY, and AS.

Expressions

An expression uses functions or maths on a column to produce a value. It can go in the SELECT list, in WHERE, or in ORDER BY.

The form
SELECT particle_speed / 2.0 AS half_particle_speedFROM physics_dataWHERE ABS(particle_position) * 10.0 > 500;

The functions available differ between databases; arithmetic, string handling and date handling exist everywhere under different names.

Integer division

An integer divided by an integer gives an integer, with the remainder discarded: 7 / 2 is 3. Writing 7 / 2.0 gives 3.5.

AS

Expressions produce unreadable column names, so they are usually given an alias. Tables can be aliased the same way.

The form
SELECT column AS better_column_name, …FROM a_long_widgets_table_name AS mywidgetsINNER JOIN widget_sales    ON mywidgets.id = widget_sales.widget_id;

A column alias can be used in ORDER BY but not in WHERE, because WHERE runs before the alias exists. That is sheet 08.

Sheet 07 · SQLBolt lessons 10 and 11

Aggregates

COUNT, MIN, MAX, AVG and SUM, then GROUP BY and HAVING.

Aggregate functions

An aggregate runs over a set of rows and returns a single value. Without a GROUP BY it runs over all the rows the query returns.

The form
SELECT AGG_FUNC(column_or_expression) AS aggregate_descriptionFROM mytableWHERE constraint_expression;
FunctionWhat it returns
COUNT(*), COUNT(column)The number of rows. COUNT(*) counts every row; COUNT(column) counts only non-NULL values.
MIN(column)The smallest value in the group.
MAX(column)The largest value in the group.
AVG(column)The average value in the group.
SUM(column)The total of all values in the group.

GROUP BY

Divides the rows into groups by the value of a column, and runs the aggregate once per group, returning one row each.

The form
SELECT AGG_FUNC(column_or_expression) AS aggregate_descriptionFROM mytableWHERE constraint_expressionGROUP BY column;

HAVING

WHERE is applied before the grouping, so it cannot test an aggregate. HAVING is applied after, and can.

The form
SELECT group_by_column, AGG_FUNC(column_expression) AS aggregate_result_aliasFROM mytableWHERE conditionGROUP BY columnHAVING group_condition;
Which one
  • WHERE — a condition on a row, before grouping
  • HAVING — a condition on a group, after aggregating

Sheet 08 · SQLBolt lesson 12

Order of execution

The order the database runs the clauses in.

The order of execution

A query is written starting at SELECT and executed starting at FROM.

RunsWhat happens
1 · FROM and JOINThe tables are read and joined, forming the full working set of rows. This happens before any condition is applied.
2 · WHERERows are tested and discarded. Can only reference columns from the tables, not aliases and not aggregates.
3 · GROUP BYThe remaining rows are grouped by the value of the grouped columns.
4 · HAVINGGroups are tested and discarded. The first point at which an aggregate exists.
5 · SELECTExpressions are computed and aliases created.
6 · DISTINCTDuplicate rows are discarded.
7 · ORDER BYThe rows are sorted. It runs after SELECT, so ORDER BY can use an alias where WHERE cannot.
8 · LIMIT / OFFSETThe slice is taken, last of all.
The order

FROM · WHERE · GROUP · HAVING · SELECT · DISTINCT · ORDER · LIMIT

Sheet 09 · SQLBolt lessons 13 to 15

Changing data

INSERT, UPDATE and DELETE.

INSERT

The form
INSERT INTO mytable(column, another_column, …)VALUES (value_or_expr, another_value_or_expr, …),      (value_or_expr_2, another_value_or_expr_2, …);

The column list can be omitted if a value is supplied for every column in the table's own order. Several rows go in one statement, separated by commas, and values may be expressions.

UPDATE

The form
UPDATE mytableSET column = value_or_expr,    other_column = another_value_or_exprWHERE condition;
The WHERE clause

An UPDATE with no WHERE updates every row in the table. Run the WHERE as a SELECT first and check what comes back before changing the verb.

DELETE

The form
DELETE FROM mytableWHERE condition;

Same warning: DELETE FROM mytable; removes every row. Where the data matters, work against a copy or a backup rather than the live table.

Sheet 10 · SQLBolt lessons 16 to 18

Changing tables

CREATE TABLE, ALTER TABLE and DROP TABLE.

CREATE TABLE

The form
CREATE TABLE IF NOT EXISTS mytable (    column DataType TableConstraint DEFAULT default_value,    another_column DataType TableConstraint DEFAULT default_value);

IF NOT EXISTS stops the statement erroring if the table is already there.

TypeHolds
INTEGER, BOOLEANWhole numbers. SQLite stores booleans as 0 and 1.
FLOAT, DOUBLE, REALNumbers with a fractional part, stored approximately.
CHARACTER(n), VARCHAR(n), TEXTText: fixed length, capped length, and unbounded.
DATE, DATETIMEA date or a point in time. Formats differ between databases.
BLOBBinary data. The database does not interpret it.

Constraints go after the type: PRIMARY KEY, AUTOINCREMENT, UNIQUE, NOT NULL, CHECK (…) and FOREIGN KEY (col) REFERENCES other(col).

ALTER TABLE

The forms
ALTER TABLE mytableADD column DataType OptionalTableConstraint DEFAULT default_value; ALTER TABLE mytableDROP column_to_be_deleted; ALTER TABLE mytableRENAME TO new_table_name;

A new column is filled with its default in every existing row, or with NULL if there is none. What ALTER supports varies between databases more than anything else here.

DROP TABLE

The form
DROP TABLE IF EXISTS mytable;
Three that get confused

DELETE FROM t WHERE … removes some rows. DELETE FROM t removes all the rows and leaves the table. DROP TABLE t removes the table itself.

If another table references this one with a foreign key, those references are left pointing at nothing, so tables are dropped in dependency order or the schema says what should happen.

Sheet 11 · SQLBolt subqueries, unions

Beyond the basics

Subqueries, and UNION, INTERSECT and EXCEPT.

Subqueries

A query returns a table, so a query can be used where a table or a value is expected.

PositionMust return
In WHERE, against = or >A single value. WHERE Rating > (SELECT AVG(Rating) FROM boxoffice).
In WHERE, against INOne column, any number of rows.
In FROMA whole table, which then needs an alias: FROM (SELECT …) AS t.

A subquery that references no column from the outer query runs once for the whole statement. A correlated subquery references the outer row and runs once per row of the outer query.

UNION, INTERSECT and EXCEPT

Set operators combine two results top to bottom rather than side to side. Both sides must have the same number of columns, in compatible types; the column names come from the first.

OperatorReturns
UNIONRows in either, duplicates removed.
UNION ALLRows in either, duplicates kept.
INTERSECTRows in both.
EXCEPTRows in the first that are not in the second. MINUS in Oracle.

One ORDER BY at the end applies to the combined result.

Sheet 13

Glossary

Every term with a card on any sheet, in one alphabet.

Aggregate functiondefinition

One that takes a whole set of rows and returns a single value about them — a count, a total, an average.

In the proper languageA function computing one value over a group of rows: COUNT, SUM, AVG, MIN, MAX. All of them except COUNT(*) ignore NULLs entirely.

Aliasdefinition

A short name given to a table or a column for the rest of the query. AS is optional.

In the proper languageA temporary name bound to a table or a select-list expression. A column alias is visible to ORDER BY but not to WHERE, because WHERE runs before the select list is computed.

BETWEENtechnique

Tests whether a value falls in a range, including both ends. BETWEEN 2 AND 5 matches 2 and matches 5.

In the proper languageAn inclusive range predicate. Equivalent to x >= lo AND x <= hi.

Clausedefinition

A keyword plus whatever belongs to it. A query is a stack of them, and they go in a fixed order.

In the proper languageA syntactic component of a statement introduced by a keyword — SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT — which must appear in that order.

Columndefinition

One fact recorded about every row, holding the same type of value all the way down.

In the proper languageA named, typed attribute of a table. Every row carries a value for it, or NULL where no value is known. Also called a field.

Databaseconcept

An organised store of information that more than one program can read and write at the same time without them treading on each other.

In the proper languageA structured, persistent collection of data managed by a database management system, which handles storage, retrieval, concurrent access and integrity.

DISTINCTtechnique

Duplicate rows. It compares the whole selected row, not each column separately, so two columns give you distinct pairs.

In the proper languageEliminates duplicate tuples from a result set, applied after the select list is computed.

Foreign keydefinition

A column in one table holding values that belong to another table's key. That shared value is the entire link between the two.

In the proper languageA column, or combination of columns, in one table whose values reference the primary key of another table, constraining the referencing rows to match an existing referenced row.

FROMtechnique

Names the table the rows are coming out of.

In the proper languageThe clause naming the source of the rows a query operates on: a table, a view, a join of several tables, or a subquery.

GROUP BYtechnique

Sorts the rows into one pile per distinct value and runs the aggregate on each pile, giving one row per pile.

In the proper languagePartitions rows into groups by the listed expressions. Every select-list column must be grouped or aggregated; engines differ on whether breaking that is an error or silently returns an arbitrary row.

HAVINGtechnique

Filters whole groups after aggregating. WHERE cannot see an aggregate because it runs before there are any groups.

In the proper languageA predicate applied to groups after GROUP BY, the first point at which an aggregate exists to be tested.

Identifierdefinition

The name of something in the database rather than a word of the language — a table, a column.

In the proper languageA name referring to a database object. Case-insensitive in SQLite and MySQL; case-sensitive when quoted in PostgreSQL. Quoted with double quotes where it collides with a keyword or contains spaces.

INtechnique

Matches any value in a list. Shorter than a row of ORs and easier to read.

In the proper languageA membership predicate over an explicit list or a subquery returning a single column.

INNER JOINtechnique

Any row without a match on the other side, from either table — silently, with nothing to tell you rows went missing.

In the proper languageReturns only the combinations satisfying the join predicate. The default when JOIN is written alone.

Joinconcept

Reading two tables as one wider table, matching rows by a value they both hold.

In the proper languageAn operation combining rows from two relations on a predicate, producing a relation over the union of their attributes.

Keyworddefinition

A word the language has reserved for itself, like SELECT or FROM. Capitals are convention, not a rule.

In the proper languageA reserved word forming part of SQL syntax. Case-insensitive; conventionally upper-cased to distinguish it from identifiers.

LEFT JOINtechnique

Every row of the first table whether it matched or not, filling the second table's columns with NULL where it did not.

In the proper languageAn outer join preserving all rows of the left relation, padding unmatched right-hand attributes with NULL. OUTER is optional and means nothing.

LIKEtechnique

Matches text against a pattern rather than exactly. % stands for any run of characters, _ for exactly one.

In the proper languagePattern-matching comparison for character data. Case-insensitive in SQLite and MySQL, case-sensitive in PostgreSQL, which is a real portability trap.

LIMITtechnique

Caps how many rows come back, applied last, after the sort. OFFSET skips that many first.

In the proper languageRestricts the result to at most n rows, evaluated after ORDER BY. TOP in SQL Server, FETCH FIRST in the standard.

Normalisationconcept

Splitting data so each fact is stored in exactly one place. It stops two rows disagreeing; the price is that answering a question now needs a join.

In the proper languageOrganising relations to reduce redundancy and update anomalies, by decomposing them so every non-key attribute depends on the key.

NULLdefinition

The absence of a value, not a value. It does not mean zero and it does not mean an empty piece of text — it means nobody knows.

In the proper languageA marker indicating that a value is unknown or not applicable. It is not equal to anything, including another NULL, so it is tested with IS NULL rather than with = .

ONtechnique

ON says how the two tables are matched; WHERE says which of the resulting rows you keep. On an outer join those are very different things.

In the proper languageThe join predicate. Applied during the join, before the WHERE clause filters the joined result — which is why a WHERE on the right-hand table turns an outer join back into an inner one.

ORDER BYtechnique

Sorts the result. Without it the order is not guaranteed — it will look stable right up until the day it is not.

In the proper languageSorts the result set on one or more expressions, ascending by default. The only construct that makes row order meaningful.

Primary keydefinition

The column whose value is different in every single row, so quoting the value picks out exactly one row and never two.

In the proper languageA column, or combination of columns, whose value uniquely identifies each row in a table. It cannot be NULL and cannot repeat. A table has at most one.

Projectionconcept

Choosing which columns come back. Choosing which rows come back is selection, and is done with WHERE.

In the proper languageThe relational operation that returns a relation over a subset of the original attributes. Distinct from selection, which restricts the set of tuples. SQL confusingly spells projection SELECT.

Querydefinition

A question put to the database. It reads and returns; it does not alter what is stored.

In the proper languageA SELECT statement: a request that returns a result set derived from one or more tables, without modifying the stored data.

RDBMSsoftware

The program that actually holds the tables and answers your SQL. Relational Database Management System. PostgreSQL, MySQL, SQL Server, Oracle and SQLite are all one.

In the proper languageRelational Database Management System: the software implementing the relational model — storage, transactions, concurrency, integrity constraints and a SQL interface over them.

Relational databaseconcept

A database that stores everything as tables that can point at each other, rather than as one big document or one long list.

In the proper languageA database organised as a set of relations (tables) of tuples (rows) over attributes (columns), where relationships between tables are expressed by shared key values rather than by stored pointers.

Result setdefinition

What comes back from a query. It is itself a table, built on the spot and thrown away, which is why a query can be fed into another query.

In the proper languageThe table of rows and columns produced by a query. It is not stored, is not named, and exists only for the life of the statement unless captured.

Rowdefinition

One of the things the table is about. One film, one customer, one order.

In the proper languageA single record in a table; one tuple, holding one value for each of the table's columns. Also called a record.

Schemadefinition

The shape of the database rather than what is in it: which tables exist, which columns each one has, and what type each column holds.

In the proper languageThe definition of a database's structure — its tables, columns, data types, keys and constraints — as distinct from the data held within it.

SELECTtechnique

Names the columns you want back. It narrows the table sideways — fewer columns, every row still there.

In the proper languageThe clause that specifies the projection: which columns, expressions or aggregates make up each row of the result set, and in what order they appear.

SELECT *technique

Returns every column, in the table's own order. Right for looking at a table you do not know; wrong for anything you intend to keep, because it silently changes shape when the table does.

In the proper languageThe wildcard projection, expanding to all columns of the source in their declared order. It is resolved at execution, so a column added later is picked up without the query changing.

SQLdefinition

The language you type at a relational database to ask it questions or change what it holds. Structured Query Language. You say what you want, not how to fetch it.

In the proper languageStructured Query Language: the standard declarative language for defining, querying and manipulating data in a relational database management system.

SQLitesoftware

A database engine that runs inside the program using it rather than as a separate server. It is what the sandbox here runs.

In the proper languageAn embedded, serverless, zero-configuration SQL database engine storing an entire database in a single file. The most widely deployed database engine in the world.

Statementdefinition

One complete instruction to the database. The semicolon is what says it has finished.

In the proper languageA single executable SQL instruction, terminated by a semicolon. The terminator is what allows several statements to be submitted together.

Subqueryconcept

A query inside another query. Because a query returns a table, it can go anywhere a table or a value is expected.

In the proper languageA nested SELECT used as a scalar, a column, or a derived table. A correlated subquery references the outer row and runs once per row of the outer query, which is where a fast report becomes a slow one.

Tabledefinition

A grid holding one kind of thing. Every row is one of them, every column is one fact about all of them.

In the proper languageA named relation: a set of rows sharing a fixed set of typed columns. Also called a relation.

UNIONtechnique

Stacks two results one above the other, adding rows. A join puts two tables side by side, adding columns.

In the proper languageA set operator combining two result sets of matching arity and compatible types, removing duplicates. UNION ALL keeps them and is faster.

WHEREtechnique

Chooses which rows come back. It is tested against every row on its own, and the row survives if the test is true.

In the proper languageThe clause restricting the rows a query operates on, evaluated per row after FROM and before any grouping.
